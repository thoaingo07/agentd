# agentd — Data access: PostgreSQL functions & procedures

**Decision:** all database access goes through **PostgreSQL functions and procedures** (PL/pgSQL),
called from C# with **Npgsql**. **There is no ORM (no EF Core).** The schema is managed by
**versioned SQL migration scripts** and applied by a small in-house runner.

Related: [Clean Architecture + BFF](clean-architecture-bff.md) · [Architecture §2.1](README.md#21-tech-stack)

---

## 1. Why

- **Concurrency-critical logic lives next to the data.** Job dequeue (`FOR UPDATE SKIP LOCKED`),
  event append + `NOTIFY`, outbox claiming, and checkpoint saves are each **one atomic database
  call**, with one round trip, instead of several ORM statements.
- **Every query is explicit and reviewable SQL**, with nothing generated by an ORM.
- **One contract per operation:** C# repositories call a named function with typed parameters.
  Schema changes stay behind that contract.

**Multi-threading:**
- A pooled `NpgsqlDataSource` (thread-safe) is registered once.
- **Each operation opens its own connection** from the pool and disposes it. A connection or
  command is never shared between threads.
- Concurrency *correctness* comes from the database: transactions, row locks, `SKIP LOCKED`, the
  `version` columns and advisory locks.

## 3. Conventions

| Topic | Rule |
|---|---|
| Schema | everything lives in the `agentd` schema; `search_path` is not relied upon, so names are always qualified |
| Naming | tables are plural snake_case (`jobs`, `events`); routines are `agentd.<aggregate>_<verb>` (`agentd.job_dequeue`) |
| Functions vs procedures | **functions** for anything that returns data (reads, and writes that return the new row or version), called with `SELECT * FROM agentd.fn(...)`. **Procedures** (`CALL`) only for void operations that manage their own transactions. |
| Parameters | named `p_<name>`, called with **positional, typed Npgsql parameters** (`NpgsqlDbType` set explicitly); never string concatenation |
| Return shape | `RETURNS TABLE (...)` with explicit columns; C# maps them by name |
| Concurrency | each mutable row has `version bigint`. Mutating functions take `p_expected_version`, update `WHERE version = p_expected_version`, and **raise `SQLSTATE 'AG409'`** when no row matched. The repository maps that to a `ConcurrencyConflict` result. |
| Errors | custom SQLSTATEs in class `AG`: `AG404` not found, `AG409` concurrency conflict, `AG422` invalid state transition. Npgsql's `PostgresException.SqlState` → Application `Error` values. |
| Transactions | one routine = one transaction whenever possible. When a use case needs several routines atomically, the repository opens an `NpgsqlTransaction` and passes it to each command. |
| Security | routines are `SECURITY INVOKER`; the app role gets `EXECUTE` on routines and no direct DML on tables (enforced from Phase 10; §6) |
| Time | `timestamptz` everywhere; `now()` inside routines, not in C# |
| JSON | `jsonb` for payloads; C# passes JSON as `NpgsqlDbType.Jsonb` |

### Example: job dequeue

```sql
-- Database/Routines/job/job_dequeue.sql
CREATE OR REPLACE FUNCTION agentd.job_dequeue(p_worker text)
RETURNS TABLE (id bigint, work_item_id int, state text, version bigint)
LANGUAGE plpgsql AS $$
BEGIN
  RETURN QUERY
  WITH next AS (
    SELECT j.id FROM agentd.jobs j
    WHERE j.state = 'Queued'
    ORDER BY j.created_at
    FOR UPDATE SKIP LOCKED
    LIMIT 1
  )
  UPDATE agentd.jobs j
     SET state = 'Preparing', claimed_by = p_worker, updated_at = now(), version = j.version + 1
    FROM next
   WHERE j.id = next.id
  RETURNING j.id, j.work_item_id, j.state, j.version;
END $$;
```

```csharp
public async Task<JobRow?> DequeueAsync(string worker, CancellationToken ct)
{
    await using var cmd = _dataSource.CreateCommand("SELECT * FROM agentd.job_dequeue($1)");
    cmd.Parameters.Add(new NpgsqlParameter { Value = worker, NpgsqlDbType = NpgsqlDbType.Text });
    await using var reader = await cmd.ExecuteReaderAsync(ct);
    return await reader.ReadAsync(ct) ? JobRow.From(reader) : null;
}
```

**Row mapping:** Dapper is allowed **for mapping results only**
(`connection.QuerySingleOrDefaultAsync<JobRow>("SELECT * FROM agentd.job_dequeue(@worker)", …)`).
It never builds SQL. Plain `NpgsqlDataReader` mapping is equally fine; use whichever is clearer
for the case.

## 4. Migration runner (`DatabaseMigrator`)

On startup (Development, and as an explicit `agentd db migrate` command in production):

1. Take a **PostgreSQL advisory lock** (`pg_advisory_lock(hashtext('agentd.migrate'))`), so
   concurrent instances never migrate at the same time.
2. Ensure `agentd.schema_migrations (version text PK, checksum text, applied_at timestamptz)` exists.
3. **Versioned scripts:** apply every `Migrations/NNNN_*.sql` that isn't recorded yet, **in order,
   each in its own transaction**, and record its SHA-256 checksum.
   - If a recorded script's checksum has changed, **fail fast**: applied migrations are immutable.
4. **Repeatable routines:** for every `Routines/**/*.sql`, compare its checksum with
   `agentd.schema_routines`. Re-run it (`CREATE OR REPLACE`) when it's new or changed. All
   routines are applied in one transaction, after the migrations.
5. Release the lock, and log what was applied.

Changing a function's **signature** (parameters or return columns) needs a versioned migration
that `DROP`s the old one first, because `CREATE OR REPLACE` can't change a return type.

## 5. Testing

- `Agentd.Infrastructure.Tests` (MSTest, `[TestCategory("Integration")]`): one Testcontainers
  PostgreSQL per assembly. `DatabaseMigrator` runs against it in `[AssemblyInitialize]`, so **the
  migrations are tested every run**.
- **Every routine has tests:** the happy path, the not-found / conflict SQLSTATEs, and a
  **concurrency test** where several parallel tasks call it at once (e.g. 20 workers calling
  `job_dequeue` claim 20 distinct jobs and none twice).
- The runner has its own tests: idempotent re-runs, fail-fast on a changed checksum, and routine
  re-apply on change.

## 6. Hardening (Phase 10)

- A separate DB role for migrations (owner) and for the app (`EXECUTE` only).
- `REVOKE ALL ON ALL TABLES IN SCHEMA agentd FROM agentd_app`.
- `statement_timeout` / `lock_timeout` defaults for the app role.
