# T0.4 — Agentd.AppHost (local orchestration)

| Phase | Depends on | Size | Layer / project |
|---|---|---|---|
| 0 | T0.2, T0.3 | M | Agentd.AppHost |

## Goal
A single command, `dotnet run --project src/Agentd.AppHost`, brings up PostgreSQL, the agentd Host
and the Vite dev server, with the Aspire dashboard showing all three.

## Files
- `src/Agentd.AppHost/Agentd.AppHost.csproj`: modify. Aspire AppHost SDK; a reference to the Host
  project; `Aspire.Hosting.PostgreSQL`; Aspire's JavaScript/Vite hosting package.
- `src/Agentd.AppHost/AppHost.cs`: create. The resource graph.
- `src/Agentd.AppHost/appsettings.Development.json`: create. Dashboard and logging settings.
- `Directory.Packages.props`: modify. The Aspire hosting packages, at the latest stable version.

## Implementation
0. **As built:** Aspire 13.5.4 with `<Project Sdk="Aspire.AppHost.Sdk">` (version pinned in
   `global.json` → `msbuild-sdks`), `<AspireUseCliBundle>true</AspireUseCliBundle>` (clears warning
   ASPIRE010), `Aspire.Hosting.PostgreSQL`, and `Aspire.Hosting.JavaScript` (`AddViteApp`). `dotnet
   run` creates `aspire.config.json` next to the project, which is committed.
1. Project SDK: use the current Aspire AppHost SDK form (`<Project Sdk="Aspire.AppHost.Sdk/<version>">`,
   or the form the current `dotnet new aspire-apphost` template generates; verify against the
   pinned version). Mark the Host reference as an Aspire project resource
   (`<ProjectReference Include="..\Agentd.Host\Agentd.Host.csproj" />`).
2. Resource graph (API names to verify against the pinned version):
   ```csharp
   var builder = DistributedApplication.CreateBuilder(args);

   var postgres = builder.AddPostgres("postgres")
                         .WithDataVolume("agentd-pgdata")          // survives AppHost restarts
                         .WithPgAdmin();                           // optional, dev convenience
   var db = postgres.AddDatabase("agentd");

   var host = builder.AddProject<Projects.Agentd_Host>("agentd-host")   // must differ from the "agentd" database resource
                     .WithReference(db)
                     .WaitFor(db)
                     .WithHttpHealthCheck("/healthz");

   builder.AddViteApp("web", "../../web")                          // Aspire JavaScript hosting integration
          .WithReference(host)                                     // exposes the Host URL to Vite via env
          .WaitFor(host);

   builder.Build().Run();
   ```
3. The Vite resource runs `npm run dev`. Make sure `npm ci` has run first: either document that as
   a prerequisite or use the integration's install option if it has one (check the pinned version).
4. Resource names are unique across *all* resource types. The database resource is `agentd`, which
   is also the connection string name, and the Host resource is `agentd-host`. The Vite resource
   reaches the Host via `AGENTD_HOST_HTTP` (or `services__agentd-host__http__0`).
   The connection string name **`agentd`** is the contract with the Host
   (`ConnectionStrings:agentd`); see T0.5 and T0.6.
5. Don't commit secrets. The PostgreSQL password is generated by Aspire and kept in the AppHost's
   user-secrets.

## Tests
- A manual smoke test, recorded in the PR: the screenshot of the dashboard shows `postgres`, `agentd-host`
  and `web` running and healthy.
- Optional (CI later): an `Aspire.Hosting.Testing` test (MSTest; `MSTest.Sdk` can enable Aspire
  testing with `<EnableAspireTesting>true</EnableAspireTesting>`, so verify that property against
  the pinned version) that starts the AppHost and asserts that `GET /healthz` on `agentd-host` returns
  200. It is marked `[TestCategory("Aspire")]` and skipped in
  CI unless Docker is available.

## Done when
- [ ] One command starts all three resources, and they turn healthy in the dashboard.
- [ ] Stopping `postgres` in the dashboard makes the `agentd-host` health check fail. Starting it again
      recovers without restarting the Host.
- [ ] Data in the `agentd` DB survives an AppHost restart (the named volume).
- [ ] The Vite dev server hot-reloads a `.vue` edit.
